# Нотатки вайб-сесії — Воркшоп 1

**Застосунок:** Tic-Tac-Toe Lab — хрестики-нулики з чотирма режимами і суперником-AI.
**Стек:** Next.js 16.3.4 (App Router) + Porsche Design System 4.6.0 + TypeScript.
**Інструмент:** Claude Code (Opus 5), Windows 10, Node 24.12.

---

## 1. Що вийшло з першого промпту, а що ні

1. **Ігровий движок — з першого разу.** `rules.ts` / `engine.ts` / `types.ts` (правила,
   узагальнена генерація виграшних ліній для 3×3–5×5, режими) скомпілювалися без
   жодної правки і більше не змінювалися по суті — лише додалося поле `turnStartedAt`.
2. **Minimax — теж з першого разу, і одразу коректний.** 480 верифікаційних партій:
   Hard не програв жодної, hard-проти-hard завжди нічия. Жодної правки алгоритму,
   окрім свідомого підняття глибини пошуку для великих дощок.
3. **Каркас з дизайн-системою — так, але не той.** Vite+PDS зібрався за одну ітерацію,
   але через 20 хвилин ТЗ змінилося на Next.js — довелося зносити теку `app/` і
   скафолдити наново. Це коштувало приблизно 15 хвилин.
4. **UI-компоненти компілювалися з першого разу, але виглядали зламано.** TypeScript був
   зелений, а на екрані клітинки були порожні й сірі. Три різні візуальні баги, яких
   `tsc` не бачив у принципі.
5. **Лінт — не з першого разу.** Правило `react-hooks/set-state-in-effect` у Next 16
   завалило 4 місця, з них 3 виявилися реальними хибами дизайну стану.

## 2. Де агент спіткнувся і як я його розвертав

| Спотикання | Симптом | Що розвернуло |
|---|---|---|
| Вигадав API дизайн-системи | `getInitialStyles` з PDS **v3**, у 4.6.0 його немає — білд упав | Читання реальних `.d.ts` у `node_modules`, а не покладання на пам'ять |
| Bare-import глобальних стилів | `@import '@porsche-design-system/components-react'` не зарезолвився; сторінка рендерилась системним шрифтом, `--p-color-canvas` порожня | Перевірка `getComputedStyle` у браузері → явний шлях `/index.css` |
| `hideLabel` на кнопці-клітинці | X та O не було видно взагалі — слот із позначкою прихований | Скріншот. `tsc` тут безсилий |
| `disabled` на зайнятих клітинках | PDS дає `opacity: .4`, тому позначки й виграшна лінія були бляклі | Інспекція `shadowRoot` кнопки; клітинки лишились активними, кліки ігнорує движок |
| Неіснуюча іконка | `icon="trophy"` — у PDS такої немає | Помилка типів + грep по списку з 293 імен |
| Граматика UI | «You wins with 3 in a row» | Заголовок став нейтральним до імені: «Winner: …» |
| Windows-специфіка | `rm -rf app` падав із `Device or resource busy` | Причина — робоча тека шелла була всередині; вихід + видалення з іншої оболонки |

Найкорисніший розворот був не промптом, а **інструментом**: щоразу, коли я переставав
вгадувати API і йшов читати те, що реально лежить у `node_modules`, помилка зникала
з першої спроби. PDS 4.6.0, до речі, постачає власну версійно-точну довідку прямо в
пакеті (`skills/pds-knowledge-react/`) — вона й виявилась головним джерелом правди.

## 4. Що зробив би інакше наступного разу

1. **Питати про стек до першого `npm create`.** Перескафолд з Vite на Next.js коштував
   ~15 хвилин і один викинутий коміт. Один додатковий уточнювальний промпт на початку
   був би дешевшим за всю цю ітерацію.
2. **Відкривати браузер раніше і частіше.** Усі три візуальні баги пройшли повз
   `tsc` і повз білд. Правило на майбутнє: після кожного нового компонента дизайн-системи —
   один скріншот, а не «зберемо все й подивимось наприкінці».
3. **Виносити алгоритм у чистий модуль і ганяти його поза UI.** Компіляція `lib/game/*`
   в CommonJS і 480 партій у Node дали більше впевненості за 30 секунд, ніж дала б
   година кліків, — і зробили безпечним підняття глибини пошуку.
4. **Ставитись до лінтера фреймворку як до рев'ювера архітектури.** `set-state-in-effect`
   не просто «поскаржився»: через нього таймер перестав рахувати секунди в стані й
   почав обчислюватись від позначки часу ходу — тепер підвисання кадру не з'їдає секунду.
